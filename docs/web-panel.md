# Web 面板

“通知 → 飞书卡片操作”按已有飞书应用群显示授权和长连接状态，read/config 只读、admin 可显式启用或撤销。页面说明群原消息收件人的两种有限权限，连接状态每五秒刷新，离开即取消请求；真实订阅与真人点击仍 Pending。接入和作用范围见 [卡片动作](card-actions.md)。

构建：Go 1.27、Node 22.22.2+（22.x）和 pnpm 11.21.0。执行 `scripts/build.ps1`，先安装锁定的前端依赖并构建，再以 webui 标签将产物嵌入 `bin/lgmon.exe`。运行编译后的 exe 不需要 Node。前端产物与 node_modules 不提交；pnpm 11 的项目设置在 web/pnpm-workspace.yaml，缓存与状态放在仓库的 dev-home/，不是 .npmrc。

在监控器运行时打开 `http://127.0.0.1:7444/`。只有直接回环访问的首页携带仅限本机的只读会话，远程首页不携带令牌。手机使用监控器允许的地址访问，在页面填写本人创建的令牌；监听和令牌创建见 [CLI](cli.md)。页面不改变监听、防火墙或服务配置。

访问令牌只保存在当前标签页会话，不写 URL、日志或 localStorage。主题偏好保存在 localStorage。服务重启使本机会话失效时重新加载首页；远程令牌失效会回到连接页面。右上角“只读 / 可配置 / 管理员”来自实际认证响应的 X-Lgmon-Scope，不能作为服务端授权依据。read 只能查看，config/admin 才显示可执行的确认与静音；后端仍逐请求检查权限。

使用 http: 且访问主机不属于回环或 Tailscale 网段时，登录表单前及页面顶部显示“正在通过不加密的 HTTP 在局域网提供面板，同一网络里的人可能截获令牌。建议改为只监听 Tailscale 地址”。按浏览器地址判断，不依据后端的 publicBaseUrl；HTTPS、localhost、IPv4/IPv6 回环和 Tailscale 地址不提示，其他 DNS 名称提示。HTTPWarning 组件只展示地址风险，不修改监听配置。

## 小窗口（U6-01）

`#/start` 是打开 lgmon 时看到的页面，在 lgmon 自己的窗口里显示（U7，见 [命令行](cli.md#打开-lgmonu6)），一屏放下、不用滚动：顶部是 lgmon 标识和“运行中”；大标题一句话结论（一切正常 / N 个服务异常 / N 个服务还没有数据 / 还没有在监控服务），下面一行是服务数、子服务数、告警数和这台电脑；服务卡片最多列 5 个，异常的在前并写原因，正常的写 24 小时可用率，其余“还有 N 个”；Agent 卡片在下方（还没有服务时是主角，有服务后变成安静的一张）；最底部是黑色的“打开看板”和“告警”“设置”，都在默认浏览器里打开。背景是柔和的彩色光晕，异常时偏暖。服务列表读不到时显示“正在读取…”或“暂时读不到状态”并自动重试，不会误说“还没有在监控服务”。由 `lgmon`（不带命令）、托盘“打开 lgmon”和安装完成页打开，见 [命令行](cli.md#打开-lgmonu6)。

## 导航与主线（U4）

外观是暖白底（深色为暖灰）、衬线标题、陶土橙强调色；状态用常见的服务可用性语汇：绿色正常、红色异常、琥珀色等待、灰色无数据，圆角竖条心跳和可用率胶囊。浅色和深色都有，默认跟随系统，侧栏底部可切换。网页标题、图标和托盘图标都是 lgmon 的“四根心跳竖条”标识。

左侧只有：面板列表（每个面板前的圆点是整体状态，异常数红字）、“新建面板”、内网里别人给我看的面板（有时才出现）、告警、内网（待处理申请数）、设置。底部是实时连接（点一下刷新）、搜索（Ctrl K）、深浅色和波西米亚（Ctrl J）。手机上侧栏收进左上角菜单。

- 首页就是第一个面板；一个面板都没有时显示欢迎页，起个名字就能新建（默认“我的服务”），也可以直接把一段话交给 Agent，它加第一个服务时会自动建面板。
- 面板（`/#/boards/<id>`）：标题、简介，“添加服务”和列表/卡片切换（每个面板记住）。上方小看板是服务数、子服务数、正常（含等待数）、异常和 24 小时可用率，有异常时异常格变红。列表每行：展开箭头（有子服务时）、可用率胶囊（颜色是现在的状态）、名称与监控对象（异常时显示原因）、24 小时心跳条、响应时间；整组异常排在最前并默认展开。点行展开子服务，点名字进入详情。卡片视图（U5-04）里每个服务可以用不同样式：心跳（可用率、24 小时心跳、响应时间，默认）、极简（大状态点和一句话）、可用率环（24 小时环和 7/30 天）、响应曲线（24 小时响应时间和当前值）、30 天（30 个日格，适合计划任务）、大数字（当前响应或可用率）；子服务在所有样式里都是卡片底部带状态点的小标签。鼠标移到卡片上，右上角出现样式按钮可以直接换；面板更多菜单的“卡片样式”打开样式库，六种样式用同一个示例服务展示并写明适合什么，可设为面板默认或给单个服务指定。样式保存在 boards.yaml 的 cardStyle / cards，内网里别人看到的也是同样的样式。超过 8 个服务时出现筛选框。不在任何面板上的服务会提示“放进这个面板”。
- 添加服务只有一个入口（U5-02）：面板右上角“添加服务”、服务详情“添加子服务”都打开同一个对话框，空面板直接内嵌同样的内容。默认是交给 Agent：一张 Agent 卡片（U6-02），一句说明它会做什么、“复制这段话”、默认收起的“显示这段话”和实时接入状态。话里不需要填写任何内容，已带面板 ID 或父服务 ID；Agent 会先问你要监控什么。接入步骤就在这段话的开头，手动接入只在“设置 → 接入 Agent”里。对话框右上角“手动创建”切到点选界面：端口 / 网址 / Windows 服务 / 进程 / 计划任务五类，除网址外都从这台电脑正在运行的列表里搜索点选（已监控的灰掉），名字自动带出，可选“挂在哪个服务下面”；那里右上角“交给 Agent”切回。只读时点“手动创建”会说明怎么获得修改权限，Agent 话术照常可用。服务列表下方和服务菜单里不再放话术。
- 服务详情（`/#/monitors/<id>`）：面包屑（面板 / 主服务 / 本服务）、状态徽章、监控对象和电脑；24 小时 96 格大心跳条、可用率与响应时间小看板（没有探测的服务改显示 7 天可用率和最近检查，HTTPS 显示证书剩余天数）、30 天日条、响应时间面积图、子服务、事件、“什么时候告警”。事件（U5-03）以异常时段为单位，覆盖本服务和全部子服务最近 7 天：先一句总结（几次异常、合计多久），再按服务分组（本服务在前，子服务按树序），每条写明服务名、开始时间（年-月-日 时:分:秒）、结束时间、持续时长、原因和期间触发的告警；正在发生的标“进行中”并显示已持续多久。恢复后只记持续满 1 分钟的异常（与 U4-11 一致）；不伴随异常的告警（例如证书快到期）也单独列出。每组默认 3 条，其余点“展开其余 N 条”。右上角“添加子服务”；更多菜单里是“编辑”（改名字、改挂在哪个服务下面；要换检查地址或告警等待时间时，编辑框底部给一段交给 Agent 的话）和删除（有子服务时提示一起删除）。
- 内网（`/#/lan`）：见 [内网共享](teams.md)。别人同意后的面板出现在侧栏“别人的面板”，打开后用同一套列表/卡片只读显示（`/#/lan/remote/<id>`）。
- 设置（`/#/settings`）：通知（飞书接入入口，“还没有设置告警通知”在这里）、电脑（CPU/内存、配置下发状态、离线缓存用量与预计时长、从服务开关导入、主机详情入口）、接入 Agent、波西米亚、网页权限、外观，以及“更多”（自定义视图、浏览这台电脑、告警卡片模板）。
- 页面顶部提醒：通知暂停、采集器配置未更新、电脑时钟偏差、离线缓存不足 24 小时、规则错误，只在有问题时出现。
- 旧地址继续可用：`#/boards/<id>` 找不到面板但有同 ID 的自定义视图时打开该视图；`#/views`、`#/alerts`、`#/notifications`、`#/hosts/...`、`#/explore`、`#/connect`、`#/teams` 仍在，只是不占主导航。

本机网页权限：以本人身份运行（个人目录）时，在这台电脑上直接打开网页即可添加服务、建面板、处理内网申请（config），界面上不出现任何权限字样。只能查看时（以系统服务运行，或从别的设备用 read 令牌打开），需要修改的按钮照常显示，点了才弹出“需要修改权限”：说明为什么现在只能看，并给出办法（本机在 settings.yaml 写 `localAccess: config`，或按本机实际路径生成令牌粘贴进来，令牌只保存在这个标签页）。修改设置和密钥需要管理员令牌，同样在被挡住时说明。设置里的“网页权限”一节写明它只在这两种情况下有用。

## 页面与数据

有自建或加入团队后，面板页出现“团队共享”分组与“团队与分享”入口。负责人用 admin 管理成员和分享；成员用 read 查看授权卡片，支持时间、主机选择及手机/深浅色，失联或撤销后清空旧数据。首次设备加入可直接打开 `/#/teams/join`，默认游客页面不显示团队入口。详见 [团队共享](teams.md)。

告警行的“诊断包”进入 `/#/alerts/<id>/diagnostics`，read 即可查看、刷新、复制交接文本并下载同一 JSON。手机和深浅色均支持，复制不可用可手动选择文本。只读范围、数据完整性和字段隐私见 [诊断包](diagnostics.md)。

| 页面 | 入口与出口 | 数据与状态 | 阶段 |
|---|---|---|---|
| 总览 | `/`，主机卡进入详情，告警区域进入告警页 | collectors、targets、firing alerts、通知配置；只读 SQL 按索引取各主机最后一条系统指标 | M1-13 |
| 主机详情 | `/#/hosts/<采集器>`，目标行进入目标详情，面包屑返回 | metrics 历史、目标/服务、最近数据缺口，以及只读启动项/计划任务、来源覆盖和最近变化（见 [清单](inventory.md)） | M1-13/M2-04 |
| 目标详情 | `/#/hosts/<采集器>/targets/<目标>`，面包屑返回主机 | 状态、探测耗时、进程 CPU/RSS 历史与时间范围内相关告警 | M1-13 |
| 告警 | `/#/alerts`，可筛选、确认或静音 | alerts；确认调用 ack；静音按规则作用于全部匹配实例，状态继续记录 | M1-13 |
| 通知 | `/#/notifications`，接入入口与返回链接 | 应用、渠道、filter、双状态模板库和规则模板选择 | M1-13/M1-14 |

| 飞书接入 | `/#/notifications/setup`，返回通知页 | 五步向导：凭据、机器人、权限、多群发现及模板、本人确认收到后保存 | M1-14 |
| 规则通知 | `/#/notifications/rules`，返回通知页 | 修改指定规则的 notify 和模板，保留其他规则字段 | M1-14 |

通知提示条在没有配置任何通知渠道时显示“还没有设置告警通知”。已有 Webhook 或 Windows 渠道时不误报未设置，通知页仍保留飞书接入入口。通知配置存在不等于已经验证本人收件。

历史范围为 1 小时、6 小时、24 小时、7 天。前两种用 raw，24 小时用 1m，7 天用 1h；状态仍取原始采样，原始清理后的缺失不由数值汇总伪造。曲线按时间排序、插入观测缺口；不把缺失值画成零，不把最后的目标状态延伸到无采样区间。离线卡片明确显示上次采样。历史过大或读取失败显示中文错误，不静默截断服务或历史列表。

SSE 用带 Authorization 的 fetch，解析分块 UTF-8、CRLF、多行 data、heartbeat 和 reset。reset 或重连触发重新读取快照；最多每秒合并刷新一次，慢请求完成后才处理合并的下一次刷新。页面、身份或筛选条件变化会取消旧请求；相同时间戳下仍通过独立版本计数刷新详情。断线显示重连状态，断线期间每 15 秒补取快照，不把旧数据当成刚更新。图表只在详情加载，离开页面释放实例，数据刷新保持实例与缩放。

## M1-14 控件绑定

五步网页向导复用 setup 的检查、测试发送和保存渠道逻辑。首次填凭据需要 admin，权限不足给出管理员令牌和 CLI 接入两种办法；config 可操作已保存应用。凭据验证后清空 Secret，不保存在浏览器存储。机器人和权限自动检查，群每五秒刷新，可同时选择多个群，各选模板、告警范围和规则，规则默认全选。确认收到前不写渠道；“没收到”列排查步骤，十秒后重发。关闭或离开页面丢弃本页收件状态，重新进入要重发。

保存先重新确认群成员关系，再合并渠道与规则。全部告警在新建时省略 filter，重置已有 filter 时显式传 {}；未修改的自定义筛选条件省略以保留。所选规则级别不在范围内时要求取消勾选，不静默删规则。规则写入失败显示已保存渠道的真实状态，链接到规则通知设置补充。服务端不记录网页确认状态，配置令牌原本就能写配置。

模板库逐个显示触发和恢复预览；预设另存为自定义模板，不能覆盖预设。基础模式与高级模式对应互斥的 extends/raw 写法，分别保留本页草稿，只保存当前模式，不声称能无损转换两种定义。基础表单支持标题、四种状态颜色、内置字段选择及顺序、附加字段、成员提醒、按钮和备注；简洁/汇总的固定布局不使用内置字段，简洁没有标题栏，对应控件禁用并说明。成员输入保留逗号和空格，不在输入过程中删掉分隔符。

前端使用锁定的 [react-markdown](https://github.com/remarkjs/react-markdown) 10.1.0 渲染文本，原始 HTML 作为文本处理，链接与图片由受控组件替换；不加载外部图片，不执行卡片按钮。支持标题栏/颜色、Markdown、两列字段、分割线、按钮和折叠面板，未知组件明确提示，深层嵌套明确停止预览。实际飞书显示仍由本人验收。

## 波西米亚（U5-05）

波西米亚是 lgmon 里的助手，标识取自本人的波西米亚（墨色云与气泡、陶土色核心，思考时转动）。它像一个熟悉这里的同事：问服务现在怎么样、最近哪里出过问题、为什么告警、lgmon 怎么用，它直接回答；也可以让它动手改已有的东西（U7）。

- 它知道你在看哪一页，也在提问时就拿到了整体情况（电脑、服务和状态、告警、面板），问现状不用再查；不会让你“去面板看看”，也不贴 http://127.0.0.1 这样的地址，要带你去别处时给站内链接。说话先给结论、正常的一句带过，不罗列正常的服务、不加表情、结尾不追问“要不要我帮你”。
- 它用的是和 Agent 一样的 MCP 工具（同一份定义、同样的校验），权限和你当前的网页相同，不会更多：改已有服务的名字和挂靠（edit_monitor）、换卡片样式和调整面板、删除服务、新建或删除面板和图表页、确认和静音告警、飞书和卡片模板、内网共享、团队与分享、远程重启已授权的服务。lgmon 的用法用 search_help 在内置说明里找（百炼向量模型找段落、rerank 排序）。
- 它不能添加新服务（需要查看这台电脑，交给能访问电脑的 Agent，从面板的“添加服务”开始），也不直接改配置文件。
- 删除、撤销、对外发消息、打开局域网可见、重启服务、邀请和分享之前，对话里会出现一张确认卡片：写明要做什么、对象和后果，点“确认”才执行，点“取消”或 3 分钟没回答都不执行。改完的东西列成改动卡片，点开去那一页。

面板在右下角，标题下的细线在思考时流动。回答进行时逐条显示它在看什么；答完收成一行“查了 N 项 · 改了 N 处 · 用时”，点开看明细；回答下面可以复制或重新回答。欢迎页有四个建议问题（现状、排查、动手、分享）。输入框下面不放提示文字，Enter 发送、Shift+Enter 换行写在发送按钮的提示里。没配置好时不报错，而是列出还差的两项（DeepSeek 的 API Key、百炼的 API Key），给出“去设置里填写”、一段交给 Agent 帮忙配置的话和本机命令 `lgmon assistant set`。

设置里的“波西米亚”一节（U5-06）与其他设置同一种样式：两行，DeepSeek（回答问题）和阿里云百炼（查说明用的向量模型和 rerank）。每行右上角显示密钥是否已保存；填密钥（保存后只显示“已保存”，要换时粘贴新的）、选模型（DeepSeek 的模型列表来自账号本身；百炼的两个模型折叠在“一般不用改”里），点“保存并测试”：先用一次小请求验证，通过才保存并显示“已连通”，失败显示原因、什么都不写。旁边有一段“让 Agent 帮我配置”的话（Agent 用 get_assistant / configure_assistant，密钥由本人提供）和本机命令。保存只需修改权限：以本人身份在这台电脑上打开的网页就能直接配置，不再要求管理员令牌。面板里的“去设置里填写”直接跳到这一节。
